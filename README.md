# Sudoku вдвоём

Мобильная PWA-игра на React + Mantine UI. Можно решать судоку одному или вдвоём с другого телефона. Совместная партия синхронизируется напрямую через WebRTC DataChannel; QR-коды используются только для ручного обмена данными подключения.

## Что уже есть

- адаптивное поле 9×9 для iPhone и Android;
- четыре сложности с уникальным решением;
- заметки и автоматическое удаление кандидатов после правильного хода;
- подсветка строки, столбца, квадрата и одинаковых цифр;
- обучающие подсказки с объяснением логики;
- отдельный счёт игроков, комбо, штраф за ошибку и подсказку;
- общий таймер и общая пауза;
- отображение выбранной клетки второго игрока;
- прямой обмен ходами, заметками и состоянием через WebRTC;
- QR-сопряжение без собственного signaling-сервера;
- автоматическая разбивка большого WebRTC-кода на несколько QR-кадров;
- ручной код как запасной вариант, если камера недоступна;
- режим одной Wi‑Fi сети без STUN;
- дополнительный режим с публичным STUN для поиска сетевого маршрута;
- локальное сохранение партии;
- PWA-манифест, service worker и иконки для домашнего экрана;
- готовый workflow для GitHub Pages.

## Запуск на компьютере

Нужен Node.js 22.12 или новее.

```bash
npm install
npm run dev
```

Открой адрес, который покажет Vite.

## Запуск на iPhone и Android

Для камеры на телефоне страница должна открываться по HTTPS. Самый простой вариант — один раз разместить статическую сборку на GitHub Pages, Cloudflare Pages или похожем сервисе. Сервер используется только для загрузки файлов приложения: игровое состояние и ходы через него не проходят.

После первого запуска приложение можно добавить на главный экран. Service worker кэширует загруженные файлы, поэтому само приложение сможет открываться без повторной загрузки сети.

### GitHub Pages

1. Создай пустой репозиторий и загрузи туда содержимое проекта.
2. В настройках репозитория открой **Pages**.
3. В **Build and deployment** выбери **GitHub Actions**.
4. Отправь изменения в ветку `main`.
5. Workflow `.github/workflows/deploy-pages.yml` соберёт приложение и опубликует папку `dist`.
6. Открой выданный HTTPS-адрес на обоих телефонах.

На iPhone: Safari → кнопка «Поделиться» → «На экран Домой».

На Android: Chrome → меню → «Добавить на главный экран» / «Установить приложение».

## Как соединить два телефона

### Полностью локально

Оба телефона должны быть подключены к одной Wi‑Fi сети. Некоторые гостевые или корпоративные сети изолируют устройства друг от друга; в такой сети прямое WebRTC-соединение может быть запрещено самим роутером.

1. На первом телефоне: «Играть вдвоём» → «Создать игру» → «Одна Wi‑Fi сеть».
2. Первый телефон показывает приглашение. Если данных много, QR автоматически меняется между несколькими частями.
3. На втором: «Присоединиться» → отсканировать QR. Сканер сам собирает все части.
4. Второй телефон показывает ответный QR.
5. Первый нажимает «Дальше — сканировать ответ» и сканирует его.
6. После открытия DataChannel игра запускается сама.

### С помощью интернета

Этот режим добавляет публичный STUN-сервер только для определения возможного прямого сетевого пути. Ходы и игровое состояние через STUN не передаются. Если оба телефона находятся за сложным NAT, без TURN прямое соединение всё равно может не получиться.

В проекте намеренно нет собственного TURN и signaling backend, чтобы сохранить простую серверless-архитектуру.

## Архитектура

```text
React + Mantine UI
        │
        ├── Sudoku engine
        │   ├── генерация
        │   ├── проверка уникальности
        │   ├── кандидаты
        │   └── объяснимые подсказки
        │
        ├── Game state
        │   ├── поле
        │   ├── заметки
        │   ├── таймер
        │   ├── пауза
        │   └── очки
        │
        └── Multiplayer
            ├── QR signaling
            ├── WebRTC DataChannel
            ├── host-authoritative state
            └── snapshot recovery
```

Создатель комнаты является источником истины. Второй игрок отправляет действие, создатель применяет его и возвращает канонический снимок состояния. Это предотвращает расхождение досок. Время паузы также фиксируется часами хоста, поэтому различие системного времени двух телефонов не влияет на общий таймер.

## Проверки

В `tests/core-check.ts` есть независимые проверки игрового движка. Они проверяют все четыре сложности, уникальность решения, валидность решённой сетки, заметки, правильный и ошибочный ход, счёт и остановку таймера.

После установки зависимостей рекомендуется выполнить:

```bash
npm run typecheck
npm run test
npm run build
```

Для ручной проверки совместной игры лучше использовать два физических телефона, потому что доступ к камере, локальной сети и ICE-кандидатам зависит от браузера и конкретной сети.

## Ограничения, о которых стоит знать

- QR не является каналом передачи ходов. После сопряжения телефонам всё равно нужен сетевой путь друг до друга.
- Полностью офлайн-режим рассчитан на одну локальную Wi‑Fi сеть.
- Гостевая Wi‑Fi сеть с client isolation может блокировать прямую связь.
- Для связи между разными мобильными сетями надёжный production-вариант обычно требует TURN-сервера. В этой версии его специально нет.
- Для сканирования QR на iPhone нужен HTTPS и разрешение камеры.

## Основные файлы

- `src/game/engine.ts` — генератор, решатель, уникальность, кандидаты и подсказки;

- `src/multiplayer/peer.ts` — WebRTC DataChannel;
- `src/multiplayer/signaling.ts` — сжатие и разбиение сигнала на QR-кадры;
- `src/components/PairingScreen.tsx` — сценарий подключения двух телефонов;
- `src/components/GameScreen.tsx` — игровой экран;
- `src/styles.css` — мобильный визуальный слой.
